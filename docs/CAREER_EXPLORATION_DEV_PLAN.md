# 职业探索 & 智能匹配 — 产品功能开发计划

> 目标：解决用户想换工作但不知道该做什么的问题，基于简历和模糊需求产出岗位方向、匹配度、技能差距、针对性简历及求职计划。

---

## 一、推荐岗位与数据来源

### 数据要求

- **岗位来源**：公开信息 + 公开 JD，不依赖付费 API
- **岗位卡片需展示**：
  - 岗位名称、示例公司、核心职责概要
  - **近一年薪资涨幅**（如 +15%）
  - **需求增速**（如 同比增长 20%）
  - **人才缺口**（如 供需比 1:3，供不应求）
  - **该岗位的市场平均薪资**（如 25–40K）
  - **该岗位的典型职业路径**（如 初级 → 中级 → 高级 → 专家/管理）

### 数据实现

- 内置「岗位库」：10–20 个热门岗位，每条包含 JD 文本 + 薪资涨幅/需求增速/缺口/市场平均薪资/典型职业路径等元数据（可从公开报告、招聘平台公开数据整理，或 LLM 基于公开信息生成并人工校验）
- 后续可扩展：接入招聘平台公开接口、爬取公开 JD 等

---

## 二、用户换工作需求（前置引导）

### 引导填写项

在「上传简历」或「开始探索」前，引导用户填写以下信息，用于更精准的岗位推荐与计划生成：

| 填写项 | 说明 | 形式 |
|--------|------|------|
| **核心诉求** | 薪资/成长/WLB/稳定性/成就感等，可多选或排序 | 多选 + 排序 |
| **可接受的薪资范围** | 如 20–35K、涨薪 20% 等 | 区间输入或选项 |
| **是否愿意换行业** | 是/否/视情况 | 单选 |
| **是否愿意换城市** | 是/否/视情况 | 单选 |

### 实现

- 作为职业探索入口的「第一步」或「可选补充」步骤
- 用户可跳过，但提示「填写后推荐更精准」
- 将上述信息一并传入岗位推荐与求职计划生成的 prompt

---

## 三、岗位匹配度（三维度）

### 匹配维度

与 Offerin 现有简历重构逻辑一致，输出三个维度得分：

| 维度 | 说明 |
|------|------|
| **技能** | 简历技能与 JD 要求的契合度 |
| **经验** | 工作年限、行业、角色与 JD 的匹配度 |
| **项目** | 项目经历与 JD 关键职责的匹配度 |

### 展示方式

- 列表/卡片展示推荐岗位，含：岗位名、公司示例、三维匹配度（可柱状图或分数）
- **点击岗位**后展开补充信息：
  - ✅ **你已具备的能力**
  - ❌ **你缺少的关键技能/经验**
  - 💡 **接下来的准备重点**
- 采用间断的信息梳理，简洁易读，不做大段叙述

### 引导下一环节

- 展开内容底部增加按钮：「生成完整求职计划」
- 点击后进入「求职计划」模块

---

## 四、求职计划（含专业学习清单）

### 计划内容

- 分阶段任务：如 准备期 / 冲刺期 / 投递期
- 每阶段含：具体任务、建议耗时、优先级
- **详细专业信息学习清单**：基于公开搜索给出 list
  - 需补充的技能/知识点 → 对应学习资源（课程、书籍、专栏等）
  - 资源来源于公开信息（B 站、极客时间、知乎、GitHub、官方文档等），可由 LLM 检索或基于预设公开资源库生成

### 计划结构要求（非「3 个月计划然后结束」）

| 要求 | 说明 |
|------|------|
| **按周拆解任务** | 计划细化到「第几周做什么」，而非笼统阶段 |
| **每个里程碑有明确的「完成标准」** | 每项任务需有可验收的完成标准（如「完成 XX 课程前 3 章」「输出一份 STAR 项目讲述稿」），不能只有「学习」等模糊描述 |
| **可打卡/标记完成** | 用户可对任务/里程碑勾选「已完成」，状态持久化（前端本地或登录后同步云端） |
| **定期回顾和调整** | 支持「回顾」入口：查看进度、未完成任务，并可触发「根据当前进度调整后续计划」（AI 根据已完成的项重新生成剩余计划） |

### 学习清单实现

- 方案 A：LLM 基于技能差距，输出结构化学习清单（技能名 → 推荐资源列表），资源链接/名称来自公开渠道
- 方案 B：内置「技能 → 公开资源」映射表，LLM 负责选出 relevant 项，再拼接具体链接
- 优先保证 list 准确、可执行，再逐步优化资源丰富度

---

## 五、针对性简历生成

### 功能

- 用户选定岗位（及 JD）后，可「一键生成针对性简历」
- 复用现有 `rewriteResumeStream` 逻辑，调整 prompt：针对目标 JD 优化表述、突出匹配经历
- 生成后进入现有简历编辑器，支持继续编辑、导出 PDF、保存到简历库

### 串联位置

- 在「点击岗位展开」的补充信息中，与「生成求职计划」并列，提供「生成针对性简历」入口
- 或在求职计划页提供「生成针对性简历」快捷入口

## 六、用量与权限

### 规则（与现有模式一致）

| 用户类型 | 职业探索模块用量 |
|----------|------------------|
| **免费用户** | 合计 3 次调用 |
| **会员用户** | 畅享，不限次 |

### 计次范围

- 「职业探索」相关所有 AI 调用合计计次，包括：
  - 岗位推荐 + 匹配度分析
  - 点击展开（✅❌💡）
  - 求职计划生成（含学习清单）
  - 针对性简历生成
- 在 proxy 中新增 `action_type` 如 `career_explore`，统一计入用量，免费用户 3 次用尽后弹 VIP 引导

## 七、功能模块清单（开发顺序）

| 模块 | 功能点 | 依赖 |
|------|--------|------|
| **1. 用户需求引导** | 核心诉求、薪资范围、是否愿换行业/城市 | 无 |
| **2. 岗位库与推荐** | 内置 10–20 个岗位（含 JD + 薪资/涨幅/缺口/平均薪资/典型路径），支持用户上传/粘贴自己的 JD | 无 |
| **3. 匹配度与展开** | 三维匹配（技能/经验/项目），点击展开展示 ✅❌💡，引导「生成求职计划」 | 模块 2 |
| **4. 求职计划** | 按周拆解 + 完成标准 + 学习清单 + 打卡完成 + 回顾与调整 | 模块 3 |
| **5. 针对性简历** | 复用 rewrite，针对 JD 生成简历，跳转编辑器 | 模块 3 |
| **6. 权限与用量** | 免费 3 次/合计，会员不限，VIP 弹窗 | 全局 |

| 阶段 | 工作内容 | 预计耗时 |
|------|----------|----------|
| **Phase 1** | 用户需求引导 + 岗位库（含平均薪资/典型路径） + 推荐与匹配度（含三维 + 展开 ✅❌💡） | 约 5 天 |
| **Phase 2** | 求职计划（按周拆解+完成标准+打卡+回顾调整+学习清单）+ 针对性简历 | 约 5 天 |

| **合计** | | **约 2 周** |

## 九、风险与后续迭代

| 风险 | 缓解 |
|------|------|
| 薪资/需求/缺口数据难获取 | 首版用人工整理的 10–20 条岗位元数据；或 LLM 基于公开描述生成，标注「仅供参考」 |
| 学习资源准确性 | 优先用知名公开渠道（B 站、极客时间、官方文档），避免失效或低质链接 |
| 免费 3 次是否过少 | 可考虑：探索+匹配算 1 次，展开 ✅❌💡 算 1 次，计划+简历各 1 次，按实际体验调整 |

**后续迭代**：接入真实岗位数据源、优化匹配算法、学习清单支持用户反馈与更新、求职计划云端同步与多端打卡、定期回顾的智能提醒

## 附录：LinkedIn / Indeed API 接入调研（2024–2025）

> 目标：评估主流招聘平台官方 API 是否可作为职业探索的岗位数据源。

### LinkedIn Jobs API

| 维度 | 结论 |
|------|------|
| **API 定位** | **Job Posting API** — 面向招聘方/ATS，用于**发布**职位到 LinkedIn，非面向求职者的职位搜索 |
| **接入模式** | 需成为 **LinkedIn Talent Solutions Partner**（填写 [Partner Application](https://business.linkedin.com/talent-solutions/ats-partners/partner-application)） |
| **申请条件** | 公司名称、网站、客户规模、5 大客户、日均活跃职位数、意向集成系统（Apply Connect / Recruiter / Talent Hub / Job Postings）等；需签署含数据限制条款的 API 协议 |
| **能力** | 创建/更新/续期/关闭职位；Basic Jobs（免费）与 Promoted Jobs（付费）；批量最多 100 条/次；限额约 10 万请求/天 |
| **认证** | OAuth 2.0 Client Credentials；Token 有效期 30 分钟 |
| **与 Offerin 匹配度** | ❌ **不匹配** — 无面向求职者的职位搜索/获取 API；官方不提供「拉取职位列表供用户浏览」能力 |

### Indeed API

| 维度 | 结论 |
|------|------|
| **API 定位** | **Job Sync API** — 面向招聘方，用于**提交**职位到 Indeed；**Publisher API**（曾提供职位搜索）已 **deprecated**（约 2021 年确认停用） |
| **接入模式** | Partner Console 申请；OAuth 2.0（3-legged / 2-legged） |
| **定价趋势** | 2024 年 Indeed 宣布 API 调用开始收费（约 $3/次）；XML Feed 将于 2025 年 3 月底全面停用 |
| **与 Offerin 匹配度** | ❌ **不匹配** — 官方无面向求职者的职位搜索 API；原 `apisearch` 等端点已不可用 |

### 结论与替代方案

| 结论 | 说明 |
|------|------|
| **官方 API 均不适用** | LinkedIn 与 Indeed 的官方 API 均面向**招聘发布**，无面向求职者的职位搜索/拉取能力；Indeed 曾有的 Publisher API 已停用 |
| **当前方案合理** | 计划中的「内置岗位库 + 公开数据/LLM 生成元数据」与「不依赖付费 API」策略与现状一致 |
| **后续可选替代** | 若需接入真实动态 JD：<br>• 第三方聚合 API：APIJobs、Adzuna、Bright Data 等（付费，有免费额度）<br>• 爬取/代理服务：HasData、SerpAPI 等（合规与稳定性需评估）<br>• 招聘平台合作：与 BOSS、智联、拉勾等国内平台洽谈数据合作 |
